需求背景

店雷达 1688 选品工作台是一个面向电商选品场景的单页应用，用户通过自然语言对话即可完成 1688 商品检索、 结果对比、报告生成与预览。当前版本已跑通核心链路，需要前后端正式对接、测试覆盖。

主要痛点：选品人员过去需要手动在 1688 多个页面来回切换、筛选、复制商品信息到表格，效率低且易遗漏。 工作台通过 AI 对话 + SSE 流式检索 + 结果信封，将选品流程收敛为一次提问。

阅读对象：前端（对接接口与渲染）、后端（接口实现与 SSE 协议）、测试（功能验收与回归）。 接口字段详情请配合 docs/前端对接文档/前端对接文档.html 使用。

原型 Demo · 结果信封三种形态

形态触发条件前端处理
有 obsUrl 返回 obsUrl + products + totalCount 右侧注册「报告」「表格」两个标签；报告 iframe 加载 obsUrl；表格渲染标准化商品
无 obsUrl + 有回答 返回 answer 文本但无 obsUrl（Agent 反问/澄清） 不判定为失败；仅展示 AI 回答文本；不注册表格标签
纯文本 仅有 answer，无任何结构化字段 聊天区显示文本；右侧保持上次结果或空状态

业务逻辑

SSE 事件协议

接口：POST /api/ai/chat/messages/stream。事件名优先取 JSON 内嵌 event 字段，其次取 SSE event: 行。

事件说明
workflow_started工作流开始，携带 conversation_id（前端用于刷新左栏标题）
node_started / node_finished工作流节点开始/结束；前端过滤「用户输入」「开始」「结束」等无意义节点，仅展示有价值的检索/分析/生成节点
message增量文本片段，追加到聊天区
workflow_finished工作流结束；携带最终 JSON 信封（answer/obsUrl/products/totalCount）
error错误事件；前端展示错误并恢复输入框

超时策略

  • 首包超时 25 秒：未收到首个事件即判定失败，提示「检索启动超时，请重试」
  • 事件间隔超时 180 秒：两个事件之间间隔超过 180 秒判定断流，提示「检索中断，请重试」

检索过程卡展示规则

  • 顶部显示当前动作标题（带脉冲动画），完成后显示「检索完成，共 X 条符合条件的商品」
  • 展示关键词标签（从用户输入解析）
  • 仅保留有价值的工作流节点；过滤「用户输入」「开始」「结束」等无意义节点
  • 节点文案具体化：解析选品需求（识别关键词、提取价格区间）、检索数据（按类目匹配）、分析对比（计算销量趋势）、生成结果（按指标排序）

AI 回答商品总数替换

AI 回答中如出现「共找到/共有/共返回/共检索到 + 数字 + 件/条/个/款/种」，需用正则匹配并替换为 totalCount 真实数据，确保文案与实际数据一致。

关键区分：前端必须区分「有 obsUrl」和「无 obsUrl + 有回答」两种场景，避免将 Agent 反问误判为失败并清空结果。

测试要点

  • SSE 首包 25 秒内到达，否则触发超时提示
  • 事件间隔超过 180 秒触发断流提示
  • 检索过程卡只展示有价值节点，无意义节点被过滤
  • 有 obsUrl 时右侧同时注册「报告」「表格」标签
  • 无 obsUrl + 有回答时，不判定为失败，不清空上次结果
  • AI 回答中的商品总数被替换为 totalCount 真实值
  • workflow_started 事件收到 conversation_id 后左栏标题立即刷新
  • error 事件后输入框恢复可输入状态

余额不足与透支处理
